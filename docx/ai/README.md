# AI 能力说明

> 说明「书遥贝贝」里的 AI 是怎么工作的：**四个 AI 触点**分别做什么、数据从哪来、怎么给模型、代价多少、以及它**看不见**什么。
>
> 对应代码：
> - `src/services/ai.js` —— 上下文拼装、问答、每日小结、一句话记一笔、本机存储
> - `src/services/ai-insight.js` —— 首页「AI 观察」（规则判断，不调模型）
> - `src/services/cloud/ai.js` —— 模型调用与模型切换
> - `src/services/parenting-knowledge.js` —— 内置育儿参考
> - `src/pages/ai-chat` / `ai-quick-record` / `record` / `index` —— 四个触点的界面

---

## 一、AI 现在出现在哪四个地方

| # | 触点 | 位置 | 用不用模型 | 干什么 |
| --- | --- | --- | --- | --- |
| 1 | **照护助手（问答）** | 底栏凸起 AI 按钮 / 工具页卡片 | 用 | 结合宝宝的记录回答问题，回答下方附「依据」 |
| 2 | **一句话记一笔** | 记录页紫色入口 | 用 | 一句话解析成结构化记录，确认可改后入库 |
| 3 | **每日小结** | 记录页「今日小结」卡内 | 用 | 主动写一段「今天怎么样」，可复制发家庭群 |
| 4 | **AI 观察** | 首页宝宝信息头下方 | **不用** | 从记录里主动发现问题（疫苗逾期、喂养/睡眠变化、便便异常色） |

前三个是「你说 / 你问，AI 回应」；第四个是「AI 自己开口」——为了让 AI 有主动性，但又不出错，第 4 个刻意用规则实现（原因见第六节）。

## 二、共用底座

### 2.1 数据从哪来

问答、每日小结（这两个共用同一份上下文）会并发拉 9 类数据，都是当前家庭 + 当前宝宝：

| 数据 | 参数 |
| --- | --- |
| 喂养 / 睡眠 / 便便 | 近 30 天，上限 800 / 500 / 800 条 |
| 最近一次喂养 | 1 条（算「距上次喂养多久、是否超上限」） |
| 生病 | 最近 20 条 |
| 生长 | 全部 |
| 疫苗 | 全部 |
| 体检 | 最近 5 次 |
| 里程碑 | 最近 20 个 |

**没有缓存**：每次提问都重查一遍。好处是刚记完一笔立刻问就能看到。

### 2.2 模型怎么调

```js
// src/services/cloud/ai.js
const ai = wx.cloud.extend.AI.createModel('cloudbase')   // 参数是模型分组，不是模型名
await ai.streamText({ data: { model: 'hy3', messages } })  // 具体模型放在 data.model
```

- **要求基础库 ≥ 3.15.1**，低了会提示「当前微信版本过低」；
- 走 `wx.cloud.init` 已有鉴权，**不需要额外登录、不需要 npm 包、不需要在控制台开通开关**；
- 没传 `temperature` 等参数，用模型默认值；
- 用 `for await (const chunk of result.textStream)` 接流，`onDelta` 做打字机效果。

### 2.3 换模型（A/B 对比）

默认 `hy3`。改默认值：`src/services/cloud/ai.js` 里的 `AI_DEFAULT_MODEL` 一行。

**不想改代码**：在微信开发者工具 Console 里执行（模拟器上下文可直接调 `wx`）：

```js
wx.setStorageSync('ai.model', 'kimi-k2.6')   // 临时换模型
wx.removeStorageSync('ai.model')             // 回到默认
```

优先级：调用方指定 > 本机覆盖 > 默认。

额度内候选：`deepseek-v4-flash` / `qwen3.5-flash` / `glm-5.2` / `kimi-k2.6` / `minimax-m3`（以控制台「AI+ → 模型」清单为准）。

### 2.4 花费

成长计划赠送的 AI 资源包自动下发到环境（10 亿 token），按 token 从资源包扣。粗算一次提问输入 3000~5000 token、输出几百 token；每日小结一天一次。家人自用这个量级用不完。

**第 4 个触点（AI 观察）不花任何额度**，纯本地规则计算。

## 三、能力一：照护助手（问答）

### 3.1 上下文三层结构

唯一的取舍是 token 成本：**近 7 天最细，近 30 天只看趋势，长期记录只给结论**。

```
宝宝档案：贝贝，生日 2025-11-20，当前 10 个月 4 天。家庭设置的喂养间隔上限：4 小时。
当前状态：最近一次喂养 2026-09-24 09:20（已过 2 小时 15 分钟）；当前有一笔睡眠进行中（从 10:05 开始）。

近 7 天汇总（按天，最后一行是今天）：
- 2026-09-23：喂养 6 次（母乳 80 分钟、配方奶 360 ml）；睡眠 13 小时 20 分钟；便便 2 次（最近一次 便 · 糊状 · 金黄）

近 7 天明细（时间正序，括号里是家长随手记的备注）：
- 2026-09-23：
  - 08:10 喂养 配方奶 120 ml（备注：喝到最后吐了一点奶）
  - 09:05 睡眠 → 10:30 · 1 小时 25 分钟
  - 22:10 睡眠 → 06:40 · 8 小时 30 分钟 · 睡到第二天

近 30 天汇总（含上面的 7 天）：
- 喂养：共 168 次，有记录 28 天，日均 6.0 次，配方奶合计 9000 ml（日均 321 ml）

长期记录：
- 疫苗：已接种 12 针，已逾期 0 针，即将接种 1 针，待接种 4 针；最近待办 麻腮风疫苗 第 1 剂（计划 2026-10-20）
- 里程碑：已达成 6 个，最近 会独坐（2026-06-10）、会爬（2026-08-02）
```

**注意「明细」这一层**：每条记录带上时刻 + 内容 + **家长备注**。这是能回答「哪一次吐奶了、隔了多久」的关键——30 天只给总量汇总，再往前完全不在上下文里。

### 3.2 「依据」那一行

回答下方显示：

```
依据：近 7 天明细、近 30 天汇总与长期记录，共 68 条原始记录
```

**由前端数出来，不交给模型自报** —— 让模型自己说「我读了多少条」每次措辞都不同，还可能是编的。条数取的是 30 天窗口内喂养 + 睡眠 + 便便的行数，所以「记一笔 → 再问 → 数字 +1」可以自证。

提示词里另有一条：引用具体记录时要带日期时间（例如「9/23 22:10 睡了 8 小时」），方便家长回记录里核对。

### 3.3 内置育儿参考

`buildKnowledgeContext()` 按两个维度挑：

1. **月龄分段要点**：取第一个 `totalMonths < maxMonths` 的档；
2. **提问命中的话题**：12 个话题按关键词匹配（发烧、腹泻、便秘、吐奶、湿疹、胀气/肠绞痛、夜醒、辅食、出牙、疫苗、感冒、断奶），一个问题最多命中 2 个。

这块是**写死在代码里的通用常识**，不是联网检索，也不是向量知识库。

### 3.4 提示词硬约束（防编造）

1. 涉及这个宝宝的数据**只能依据「宝宝的情况」里的记录**，没有的就直说「记录里看不到」，不许猜数字；带「（备注：…）」的是家长随手记的特殊情况，要一并考虑；
2. 通用发育/照护问题可以答，但要说清是通用建议；
3. 先讲事实再给建议，依据不足就直说；引用记录要带时间；
4. 中文、简短分点、适合手机看；
5. **不能替代医生**，明确列出需要就医的情况；
6. 不评判家长、不说教、不给用药剂量。

### 3.5 对话历史

- **只存在这台手机上**（key = `ai_chat_history:用户ID:宝宝ID`），按「账号 + 宝宝」分开；
- 最多保留 200 条（约 100 轮）；
- 每次提问只取最近 **12 条**进模型（约 6 轮）；
- 「依据」不写进历史，所以重进页面后恢复的历史气泡没有依据行（设计如此）。

## 四、能力二：一句话记一笔

「像跟家人说话那样描述，AI 帮你填好字段，你确认后才写库。」

### 4.1 支持六类

| 类型 | 例子 | 落库字段 |
| --- | --- | --- |
| 喂养 | 「刚喂了 120 毫升配方奶，有点吐奶」 | 方式 / 奶量 / 时长 / 时间 / 备注 |
| 睡眠 | 「睡了 40 分钟」 | 入睡 + 睡醒（由「睡醒 − 时长」推出） |
| 便便 | 「半小时前拉了稀便，绿色的」 | 类型 / 性状 / 颜色 / 时间 |
| 生长 | 「今天量了身高 74，体重 9.1 公斤」 | 身高 / 体重 / 头围 / 日期 |
| 生病 | 「有点发烧 38.5 度，还流鼻涕」 | 症状（8 项枚举，可多选）/ 体温 / 时间 |
| 里程碑 | 「今天第一次会翻身了」 | 名称（不在预置表里就记为自定义） |

**疫苗与体检不做**：它们要跟疫苗库的名称剂次、体检记录对上号，说错一个名称就记错一条，不如手动排更稳。

### 4.2 怎么保证不写错

1. **只要 JSON**：单独一个提示词，不用问答那套 system prompt（不需要上下文，省 token 也更稳）；
2. **剥 JSON**：模型偶尔包 ```` ```json ```` 或前后多说一句，取第一个 `{` 到最后一个 `}` 再 `JSON.parse`；
3. **逐字段按业务枚举校验**：喂养方式、便便性状颜色、症状、里程碑 key 都从各 service 的常量表推导（`FEED_TYPE_LABEL` / `DIAPER_TYPES` / `POOP_*` / `ILLNESS_SYMPTOMS` / `MILESTONE_PRESETS`），表里没有的一律置空；
4. **数值区间校验**：超范围**抛错并带上具体数值**（「体温 88 超出正常范围（30~45），请手动记录」），而不是安静地丢掉字段——丢了家长会以为记上了；
5. **时间由「几分钟前」换算**：让模型算相对时间比让它拼日期靠谱。

`assertQuickRecord()` 是校验 + 归一化的统一入口，**解析后跑一次、提交前再跑一次** —— 确认卡上的字段可编辑，用户改过的值同样是外部输入。

### 4.3 确认卡：每个字段都能改

- 时间用日期 + 时间选择器；枚举（方式 / 性状 / 颜色 / 症状）用点选 chips；数值用数字输入框；备注用文本输入；
- **睡眠**：改时长或睡醒时间，入睡时间自动重算，不会自相矛盾；
- **生长 / 里程碑**：库里只存日期，改时间时日期同步；
- **便便切成「尿」**：性状与颜色自动清空（与 `services/diaper.js` 的归一化口径一致）；
- **里程碑改名**：自动按「自定义」记，否则列表里会被预置名盖回去。

**类型本身不给改**：AI 认错类别时，点「重新说」或返回手动记更省事。

界面用一张 `KIND_HANDLERS` 表描述「每种记录怎么落库」，再加类型只需补一项。

## 五、能力三：每日小结

- 位置：记录页「今日小结」卡底部；进页面时**自动补一次**（当天有记录、又没生成过才会跑），也可以手动点／重新生成；
- 输出：3~4 句中文，和前几天比一比、点出备注里的特殊情况、给一条可执行的小建议；要求不下医学结论、不用「建议咨询医生」笼统收尾；
- **一天只成功一次**：结果按 `账号 + 宝宝 + 日期` 缓存在本机（key = `ai_daily_summary:...`），同一天再进页面只读缓存；
- 失败会退回按钮让用户手动点，不会因为反复进页面而反复请求；
- 「复制」直接发家庭群（写剪切板属隐私接口，先过 `ensurePrivacyAuthorized`）。

## 六、能力四：AI 观察（首页）

**刻意用规则、不用模型**：

1. 观察要的是**准**——规则算错了能一行行查；模型每次措辞不同，反而分不清哪句真哪句是顺口编的；
2. 打开首页就该看到，不该等几秒，也不该花额度。

规则优先级（命中第一条就返回）：

| 优先级 | 规则 | 阈值 |
| --- | --- | --- |
| 1 | 便便颜色异常（带血丝 / 黑） | 近 7 天内出现过 |
| 2 | 疫苗逾期 | 有到接种时间还没记录接种的 |
| 3 | 喂养次数变少 | 近 3 天日均 vs 前 4 天日均，降幅 ≥ 25%，且前 4 天日均 ≥ 3 |
| 4 | 睡眠时长变短 | 降幅 ≥ 20%，且前 4 天日均 ≥ 8 小时 |
| 5 | 都正常 | 给一句现状（每天喂几次、睡多久、换尿布几次） |

- **窗口与对比天数都写死在上限里**：7 天窗口、近 3 天 vs 前 4 天；
- 前 4 天本来就很少时不做对比（样本太小，报了反而误导）；
- 查不到数据就安静地不显示，**不能影响首页**；
- 点卡片会带着对应的问题进 AI 助手（`?q=...` 自动填进输入框，不自动发送、不自动花额度）；
- 边界：只陈述数据上发生了什么 + 什么情况该就医，**不下任何医学结论**。

## 七、它看得见什么、看不见什么

**看得见**

- 近 7 天每一条喂养 / 睡眠 / 便便：时刻、内容、**备注**
- 近 7 天按天汇总；近 30 天总量与日均
- 当前状态：距上次喂养多久、是否超上限、是否正在睡
- 长期记录结论：生病最近 5 条（症状/体温/诊断）、生长首末对比、疫苗统计与最近 3 个待办、最近一次体检（含发育评估与医生建议）、最近 8 个里程碑
- 宝宝档案：名字、生日、月龄、家庭喂养间隔上限

**看不见**

- **照片本身**（图片不会发给模型）；照片备注也没纳入
- **生病 / 生长 / 疫苗 / 体检 / 里程碑这几类的备注**（只取症状、体温、诊断、数值等结构化字段）
- **7 天以前的逐条明细**（只有 30 天汇总数字）；**30 天以前的记录完全没有**
- 家庭里其他宝宝的记录（只带当前宝宝）
- 站外信息（没有联网检索，常识全靠内置那份参考）

## 八、排查手册

**日志**：每次提问都会打一行，在开发者工具 Console：

```
[AI] 提问 { babyId: '...', 历史条数: 2, 上下文长度: 3480, 通用参考长度: 620 }
[AI] 一句话记一笔 { kind: 'feeding', minutesAgo: 0, 原始长度: 128 }
```

- `上下文长度` 只有几百 → 数据没取到（检查当前家庭/宝宝选对没）；
- `通用参考长度` 为 0 → 问的话题没命中话题表（正常，模型仍会答通用建议）。

**常见报错**

| 提示 | 原因 |
| --- | --- |
| AI 助手当前不可用（仅微信小程序端 + 云开发后端提供） | 跑在 H5 或 Supabase 后端 |
| 当前微信版本过低，请更新微信后重试 | 基础库 < 3.15.1 |
| 当前环境不支持微信云开发 | `wx.cloud` 没初始化 |
| XX 超出正常范围（…），请手动记录 | 一句话记一笔的数值校验拦下了 |
| 没听清这句 | 模型没解析出可用字段，换说法或手动记 |

**想调参数**（都在 `src/services/ai.js` 顶部）

| 常量 | 当前值 | 作用 |
| --- | --- | --- |
| `CONTEXT_DAYS` | 7 | 逐条明细 + 按天汇总的天数 |
| `OVERVIEW_DAYS` | 30 | 总量/日均汇总的窗口 |
| `HISTORY_LIMIT` | 12 | 带进模型的历史条数 |

观察的阈值在 `src/services/ai-insight.js` 顶部（`FEED_DROP_RATIO` / `SLEEP_DROP_RATIO` 等）。

## 九、隐私边界（重要）

宝宝的喂养 / 睡眠 / 便便 / 生病 / 生长 / 疫苗 / 体检 / 里程碑记录，**包括家长写的备注原文**，都会作为上下文发给大模型。目前是「只给家人用、不公开发布」的自用形态，**没有做脱敏**。

AI 对话与每日小结**只存在本机**，不上云。

若将来要对外发布，必须先在这些地方加一层脱敏（把名字换成「宝宝」、去掉可识别信息）再发出去。
