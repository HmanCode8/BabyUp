# 需求文档归档

这一节按**时间顺序**保存项目推进过程中产生的原始需求文档与决策记录。
它们记录的是「当时要求做什么」，**不保证与今天的代码一致**——
看当前实现请以[代码架构](/guide/architecture.md)、[数据模型](/guide/data-model.md)、[功能地图](/guide/features.md) 为准。

> 早期文档里写的「**初芽（BabyUp）**」就是现在的「**书遥贝贝**」，同一个产品改过名字，
> 不是两套代码。文档正文保持原样未改，只在标题处保留原貌。

## 演进主线

```text
一期（核心记录闭环）
  └─ 二期（家庭权限 / 多宝宝 / 成长报告）
       └─ 一二期补丁（上线前置：找回密码、注销、导出、隐私政策、分享、埋点）
            └─ 三期（Supabase 版：订阅消息、AI、疫苗库 …）
                 ├─ 三期（云开发版）← 取代上一份，成为实际开发依据（2026-09-21）
                 └─ 双后端迁移计划（把 Supabase 实现迁到微信云开发，两版并存）
```

## 读归档时的几个提醒

1. **架构前提变了**：一期到三期（Supabase 版）都假设后端是 Supabase + Edge Function + RLS。
   现在实际运行在**微信云开发**上，`RLS`、`Edge Function` 这些词要按[双后端总览](/backend/README.md)重新理解。
2. **不再成立的功能**：手机号登录、邮箱找回密码、绑定真实邮箱这几项在云开发侧没有对应能力，
   代码仍在 Supabase 版里保留，但当前形态下不渲染、不走通。
3. **金额与会员**：三期 Supabase 版里的会员/支付相关内容没有实施（项目定位是家人自用、不收费）。
4. **疫苗库口径**：云开发侧比 Supabase 侧多几条疫苗种子数据，两边的 `sort_order` 也不同步，
   这是有意保留的现状，详见 [数据模型](/guide/data-model.md) 里标注的「未确认 / 不一致」清单。
5. **各文档自带的「分步开发计划 / 验收清单」**：是当时的施工单，已完成的部分不必再照着走。
