- ❌ 会员订阅、微信支付、订单体系、容量配额（要钱 / 依赖会员）
- ❌ AI 育儿助手（要外部账号 + 合规风险）

### 2.4 三期验收一句话

> 我在微信里打开小程序 → 记录一次喂养、一张照片 → 去"我的"提交一条反馈 → 记录宝宝一次生病用药、一次儿保体检（体检身高自动进生长曲线）→ 年底生成一份年度报告长图保存到相册并转发到家庭群 → 疫苗到期时**我和家人都能收到**订阅消息 → 全程无需付费、无外部依赖、数据隔离正常。

## 三、架构与约束（微信云开发）

### 3.1 双后端并存（现状，不要改动这个结构）

```
业务代码 ──► src/services/api.js（唯一切换点）
                 │
      BACKEND === 'cloud' ？
        ├── 是 ──► src/services/cloud/**   （微信小程序端，当前生效）
        └── 否 ──► src/services/supabase/**（H5 端自动回落 / 整体回滚用，永远保留）
```

- 两套实现必须保持**同形契约**：新增记录类型时，**云端与 Supabase 端都要实现同名方法**，否则切回 Supabase 时 H5 会报错。
- 新增集合/表时，云开发建集合（`init-db`），Supabase 侧也要有对应建表 SQL，保持可回滚。
- H5 不作为对外产品，仅作开发期回滚通道。

### 3.2 云函数清单

**现有 6 个**：

| 云函数 | 职责 |
|---|---|
| `login` | 微信一键登录，换取 openid / 建 profiles |
| `data` | **通用数据网关**：所有业务读写都走它（`action` 分发），内置 `assertMember` 家庭鉴权 + `grabInsert/guardUpsert/guardRemove` 写保护；含 `tempFileURL` / `deleteFile` 文件代理 |
| `init-db` | 建 14 集合 + 疫苗库种子数据 |
| `reminder` | 定时任务（每日 09:00）下发疫苗订阅消息 |
| `delete-account` | 账号注销 |
| `export-data` | 数据导出 |

**本期新增：0 个。** 三期所有新功能（反馈、生病用药、儿保体检）都通过 **`data` 云函数的 `action` 机制**实现，沿用既有鉴权链，不新建云函数。

> 唯一例外：若年度报告要做"小程序码"（可选增强），需在 `data/config.json` 的 `permissions.openapi` 中增加 `wxacode.getUnlimited`，并**重新上传部署 `data` 云函数**。此项非必需（转发卡片已自带入口）。

### 3.3 云数据库集合

**现有 14 个**（`init-db` 中 `COLLECTIONS` 常量，与 Supabase 14 张表一一对应）：
`families`、`family_members`、`family_invitations`、`babies`、`baby_photos`、`growth_records`、`vaccinations`、`feeding_records`、`sleep_records`、`diaper_records`、`milestones`、`profiles`、`vaccine_library`、`app_logs`

**本期新增 3 个**：`feedbacks`、`illness_records`、`checkup_records`（字段定义见第五节）。

**落地方式**：在 `init-db/index.js` 的 `COLLECTIONS` 数组末尾追加这 3 个名字，重新部署并执行一次 `init-db`（`createCollection` 对已存在集合会报错，现有代码已做"已存在"容错，重复执行安全）。**执行前先把改动展示给用户确认。**

### 3.4 云开发免费额度与约束（影响设计的硬条件）

| 项 | 额度/约束 | 对本期的影响 |
|---|---|---|
| 存储容量 | 5GB | 体检本/病假条拍照上传需限制张数与体积 |
| 下载流量 | 5GB/月 | 分享长图走本地 canvas，不再上传，避免白耗流量 |
| 云函数调用 | 4 万资源点/月 | 定时任务保持每日 1 次；避免轮询式设计 |
| 云存储权限 | **免费套餐不可修改**（当前为"仅创建者可读写"） | 所有跨成员文件访问**必须**走 `data` 云函数代理 |
| 公网静态托管 | 需付费/单独开通 | 不做网页版只读分享 |

### 3.5 云存储访问约定（方案 A，已上线，勿改回）

- 客户端**不得**直接调 `wx.cloud.getTempFileURL`：它受云存储安全规则限制，在"仅创建者可读写"下只能换出自己的文件，表现为**家人之间互相看不到照片**。
- 正确路径：`src/services/cloud/storage.js` → `callData({ action: 'tempFileURL' | 'deleteFile' })` → `data` 云函数以**管理员身份**调用，不受安全规则约束。
- 业务表里始终存**相对路径** `{familyId}/{babyId}/...`，`CLOUD_FILE_ID_PREFIX` 只在调 `wx.cloud` 接口前拼上。
- **fileID 三段结构（曾因此出过 bug，务必注意）**：
  `cloud://<环境ID>.<存储桶ID>/<family_id>/<baby_id>/<文件名>`
  `cloud://` 后**第一段是平台自动拼的"环境ID.存储桶ID"，第二段才是 family_id**。解析鉴权信息时取第二段。

### 3.6 定时任务

- `reminder` 已有 timer 触发器：`config.json` 中 `"config": "0 0 9 * * * *"`（每日 09:00）。
- 若儿保体检要加"下次体检提醒"（P0-4 可选增强），**复用同一个 timer 里的处理分支**，不要新增触发器（省资源点）。

### 3.7 新增页面的路由

- `src/utils/routeGuard.js` 只登记了三类特例：`PUBLIC_PAGES`（login/forgot-password）、`OPEN_PAGES`（privacy/terms）、`GUIDE_PAGES`（setup/join-family）。
- **其余页面默认即"受保护"**（需登录 + 已有家庭）。本期新增的 feedback / illness / checkup / annual-report 全部属于此类，**无需修改 `routeGuard.js`**，但**必须在 `src/pages.json` 中注册**。

## 四、功能设计

### 4.1 P0-1 上线收尾（硬阻塞，最先做）

**现状**：迁移计划中记录，当前唯一硬阻塞是 **mp 后台「用户隐私保护指引」未声明相册/摄像头权限**。

**要做的事**：

1. **补隐私指引声明**（需用户在 mp.weixin.qq.com 后台操作，Agent 只出说明）：
   - 涉及接口：`wx.chooseMedia`（拍照/选图，用于照片、里程碑、体检本、病假条）、`wx.saveImageToPhotosAlbum`（保存报告长图）。
   - 在「设置 → 服务内容声明 → 用户隐私保护指引」中，按后台**当前实际提供的条目名称**勾选摄像头、相册相关条目；不要照抄文档里的旧名称，以后台显示为准。
   - 提交后等待审核通过。
2. **验证照片互见闭环**（此前未最终确认）：
   - 开发者工具「编译」→ 右上角「上传」（版本号递增）→ 公众平台「版本管理 → 选为体验版」→ 家人**删除旧小程序缓存后重新进入**。
   - 判定标准：用户上传的照片，家人在时光页能正常显示；反之亦然。
   - 若仍失败，收集家人端现象（裂图 / 控制台报错）后再定位——**不要盲目改动已修好的 `familyIdOfFile` 逻辑**。
3. **清理遗留**：删除云端 `ping` 云函数（迁移计划中记录的待办）。
4. **订阅消息状态**：`src/cloudfunctions/reminder/index.js` 中 `MINIPROGRAM_STATE` 当前为 `'trial'`（体验版）。**正式发布后**改为 `'formal'` 并重新部署。

**验收**：隐私指引审核通过；家人端能看到对方上传的照片；云端无 `ping` 云函数。

### 4.2 P0-2 用户反馈

**目标**：让用户能把问题/建议发上来（上线产品的最低要求）。

**页面**：`pages/feedback/feedback`（新增）
- 入口：`src/pages/profile/profile.vue` 在"数据与备份"附近加一行「意见反馈」。
- 表单字段：
  - 反馈类型（单选标签）：功能异常 / 体验建议 / 内容有误 / 其他
  - 问题描述（必填，最少 5 字，最多 500 字）
  - 截图（可选，最多 3 张，走现有 `uploadObject` 上传，路径 `{family_id}/feedback/{唯一串}.jpg`）
  - 联系方式（可选，微信/手机号，用于回访）
- 提交成功后：清空表单 + toast「已收到，感谢反馈」+ 返回上一页。
- 再点进入可看到自己历史提交记录（状态展示为"待处理/已处理"，只为给用户反馈感，不做工单系统）。

**数据**：新增集合 `feedbacks`（见 5.1）。

**服务端**：`data` 云函数新增两个 action：
- `submitFeedback`：写入，`created_by` 由服务端从 `cloud.getWXContext().OPENID` 注入，**不接受前端传入**；长度与类型做服务端校验。
- `listMyFeedback`：仅返回 `created_by === 当前 openid` 的记录（不能看别人的）。

**隐私**：反馈含"联系方式/截图"，属个人信息收集，**必须同步更新隐私政策文案**（在 `src/pages/privacy/privacy.vue` 中加入反馈场景的说明）。

**管理端**：本期**不做**反馈后台页面，数据在云开发控制台数据库里直接看。这点要在交付说明里写给用户。

**字段**：
| 字段 | 说明 |
|---|---|
| `occurred_at` | 发病时间（必填） |
| `symptoms` | 症状标签多选：发热 / 咳嗽 / 流涕 / 呕吐 / 腹泻 / 皮疹 / 食欲差 / 其他（必填至少 1 项） |
| `temperature` | 体温 ℃（可选，数值） |
| `medicines` | 用药数组：`[{ name, dose, unit, frequency, days, note }]`（可选，可加多行） |
| `hospital` / `doctor` / `diagnosis` | 就诊医院 / 医生 / 诊断（均可选） |
| `allergy_note` | 过敏/不良反应记录（可选，纯文本） |
| `photos` | 图片数组（可选，最多 3 张，路径 `{family_id}/{baby_id}/illness/{唯一串}.jpg`） |
| `note` | 备注（可选） |

**入口**：`src/pages/record/record.vue` 的快捷入口网格当前是 7 项（拍照片 / 量一量 / 打疫苗 / 喂奶 / 睡觉 / 便便 / 里程碑），**增加一项「生病」凑成 8 项（4×2 网格）**，跳到 `pages/illness/illness`。

**不做**：不把生病记录混进时光页照片流（避免污染以照片为主的浏览体验）。

**医疗免责**：列表页与编辑页底部各放一行浅灰小字「本记录仅用于家庭内部留存，不构成医疗建议，请遵医嘱」。这是合规表达，不是功能。

### 4.4 P0-4 儿保体检记录

**目标**：留存儿保本数据，并让体检的身高体重自动进入已有的生长曲线。

**页面**：
- `pages/checkup/checkup`（列表，新增）：按体检日期倒序；卡片显示"日期 + 月龄 + 身高/体重"；若有 `next_date`，显示"距下次体检还有 N 天"。
- `pages/checkup-edit/checkup-edit`（新增/编辑，新增）：同 4.3 的页面范式。

**字段**：
| 字段 | 说明 |
|---|---|
| `checkup_date` | 体检日期（必填） |
| `month_age` | 月龄，**由 `checkup_date` 与宝宝生日自动计算**，前端只读展示，不手填 |
| `hospital` | 体检机构（可选） |
| `height_cm` / `weight_kg` / `head_cm` | 身高 / 体重 / 头围（均可选，数值） |
| `hemoglobin` | 血红蛋白（可选，数值） |
| `development` | 发育评估（可选，文本） |
| `doctor_advice` | 医生建议（可选，文本） |
| `next_date` | 建议下次体检日期（可选，用于提醒） |
| `photos` | 体检本照片（可选，最多 3 张，路径 `{family_id}/{baby_id}/checkup/{唯一串}.jpg`） |

**联动（本项的关键价值）**：保存体检记录时，**若填了身高或体重，同时往 `growth_records` 写一条同日期、同数值的记录**（来源标记为体检导入），这样生长曲线自动连上，用户不用再手填一次。
- 实现要点：写入必须保持两者一致；**编辑体检记录时若改了身高体重，需同步更新对应的生长记录**；删除体检记录时给出选择（"同时删除关联的生长记录" / "保留"）。此联动逻辑要写在 **`data` 云函数内**（服务端事务式处理），不要放在前端分两步写，否则会出现半写状态。

**提醒（可选增强）**：`next_date` 到期前复用 `reminder` 云函数的每日 timer 增加一个分支下发订阅消息。此项**仅在有剩余精力时做**，需注意订阅额度是一次性的（见 4.6）。

**明确不做**：**WHO 百分位自动评估**。已核查代码库当前**没有**任何百分位实现，做它需要引入 WHO 标准数据表 + 算法，属独立课题，本期不承诺。

### 4.6 P1-6 订阅消息补全：家人也能收到

**现状**：
- 客户端授权入口**已有**：`src/pages/vaccine/vaccine.vue` 在用户添加疫苗记录时同步调用 `uni.requestSubscribeMessage`（微信要求必须由用户点击手势直接触发，代码已按此实现，且授权失败一律静默、不阻断记录保存）。
- 服务端下发**已有**：`src/cloudfunctions/reminder`，每日 09:00，模板 ID `9-P4ftotXMMapWSvVhH578lFR0LV4qvLewPMYyA0dns`。
- **缺口**：`reminder/index.js` 只发给 `record.created_by`（疫苗记录的创建者）。**家里的其他成员收不到提醒**——这是最影响体验的一点。

**要做的改动**：
1. `reminder` 云函数：把下发对象从单个 `created_by` 改为"**该宝宝所属家庭的全部成员**"，逐个下发。
2. **额度现实**：微信订阅消息是一次性的——**每个用户必须自己授权过，才有 1 条该模板的发送额度**；未授权的成员发送会失败（错误码 43101）。因此：
   - 发送时**必须逐个 try/catch**，失败即跳过并记日志，绝不能因为某个成员没额度而导致整批中断（现有代码已有单条 catch，扩展为循环即可）。
   - 每个家庭成员都需要有授权入口。除了现有的"添加疫苗记录时授权"，**建议在 `pages/vaccine/vaccine.vue` 顶部加一个「开启疫苗提醒」按钮**，让不做记录的家庭成员（如爷爷奶奶）也能主动授权。这是本次改动的重点。
   - 授权结果**不落库**：微信不提供查询用户剩余订阅额度的接口，只能"发失败即停"。**不要**为此设计一张额度计数表然后拿它当准数（会不准）。
3. 文案：页面上说明"微信提醒次数有限，站内疫苗待办始终可见"，避免用户以为漏推是 bug。

**验收**：两个家庭成员**各自**在小程序里点过授权后，疫苗到期日**两人都能收到**订阅消息；未授权的那一位不影响另一位收到。

## 五、数据模型（本期新增集合）

> 约定：所有业务集合统一包含 `family_id`、`baby_id`、`created_by`（存 openid）、`created_at`、`updated_at`。这三个字段**由 `data` 云函数服务端注入**，前端不传、也传不进来。`_id` 与 `id` 由 `data` 云函数做透明映射。
>
> 落地时注意：云开发是文档型数据库，**不需要建表 SQL**，只需在 `init-db` 的 `COLLECTIONS` 数组里加集合名；字段靠写入时自然形成。**执行前先展示给用户确认。**

### 5.1 `feedbacks`（用户反馈）

```
_id, user_id, created_by, content, type, contact, images[], status, created_at, updated_at
```
- `type`：`bug` | `suggestion` | `content` | `other`
- `status`：`pending` | `done`（默认 `pending`）
- `images`：云存储相对路径数组（最多 3）
- 无 `family_id`/`baby_id`（反馈是账号维度的，可能用户在还没建家庭时就要反馈）

### 5.2 `illness_records`（生病 / 用药）

```
_id, family_id, baby_id, occurred_at, symptoms[], temperature,
medicines[{ name, dose, unit, frequency, days, note }],
hospital, doctor, diagnosis, allergy_note, photos[], note,
created_by, created_at, updated_at
```

### 5.3 `checkup_records`（儿保体检）

```
_id, family_id, baby_id, checkup_date, month_age,
hospital, height_cm, weight_kg, head_cm, hemoglobin,
development, doctor_advice, next_date, photos[],
created_by, created_at, updated_at
```

### 5.4 两侧同步要求（可回滚）

每新增一个集合，**Supabase 侧必须同步建对应表**（`supabase/**` 目录下的建表 SQL 文件），字段保持一致，RLS 策略沿用既有风格。否则把 `BACKEND` 切回 `supabase` 时 H5 会在这些表上报错。这是"双后端并存"的成本，必须付。

## 九、风险与注意事项

1. **云存储权限是死结，别再去试**：免费套餐下控制台改权限会被拦。照片访问一律走 `data` 云函数代理，**不要试图改回客户端直连 `wx.cloud.getTempFileURL`**。
2. **fileID 解析取第二段**：`cloud://` 后第一段是"环境ID.存储桶ID"。此处曾因取错段导致"所有图片都加载失败"，是全站级故障。
3. **客户端与云函数是两个独立发布通道**：`data` 云函数改动只对**新版本客户端**生效；只部署云函数、不上传小程序代码，家人端不会有任何变化。**每次改完都要走"上传 → 设体验版 → 家人清缓存"三步。**
4. **订阅消息是一次性的**：没有"长期推送"这回事，也没有查询剩余额度的接口。所有设计不能假设"用户能持续收到"。
5. **`store.membership` 不是付费会员**：它指"当前家庭里的成员身份记录"（含 `family_id`/`role`）。本期不引入任何付费语义，命名上不要混淆。
6. **体检↔生长联动必须服务端完成**：前端分两步写会产生半写状态（体检存了、生长没存）。
7. **WHO 百分位本期不做**：代码库当前没有百分位实现，不要在验收里承诺它。
8. **隐私政策要跟着功能走**：新增"反馈（联系方式/截图）"的收集说明。未来若做体检照片，也要一并声明。
9. **免费额度要有意识**：体检本/病历照片会吃存储与流量，上传处限制张数（建议 3 张）并做尺寸压缩。
10. **不要引入新依赖**：canvas 出图、图片压缩等现有代码已够用（`report.vue`、`photo.js`）。

## 十、给 Agent 的执行规则（必读）

1. **先看代码再动手**：本文档描述的是**当前代码库的状态**。动手前先读对应文件确认现状，文档与代码不一致时**以代码为准并立即向用户报告**。
2. **禁止自行假设**：遇到文档未覆盖、API 行为不明、或需要产品决策的地方，**停下来列问题问用户**，不要"顺手"选一个方案做掉。
3. **建集合 / 部署云函数 / 执行任何会造成不可逆影响的操作前，先把内容展示给用户确认**。改账号注销相关功能只用测试账号验证。
4. **不删代码、不改写 Supabase 侧**：`src/services/supabase/**` 与 `supabase/**` 必须保持可用，新功能要在两侧同步补齐同形实现。
5. **不花钱**：不申请付费服务、不开通付费套餐、不引入需要付费的第三方 API。
6. **每次改动后构建验证**：`npm run build:mp-weixin`，确认退出码为 0，并核对产物（devtools 监视目录是 `dist/build/mp-weixin`）。
7. **改动范围最小化**：只改与当前 Step 相关的文件，不做顺手重构、不提前实现后续 Step 的内容。
8. **每完成一个 Step**，用一句话汇报：改了哪些文件、自测结论、遗留问题。
