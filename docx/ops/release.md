### 0.1 小程序主体：个人主体（已确认）

**结论：个人主体。** 你已在后台「设置 → 基本设置 → 主体信息」核对过了。

**关于你说的「微信认证」**：微信官方那个 300 元/年的「微信认证」，入口是给**企业、政府、媒体、其他组织**用的（[官方说明](https://developers.weixin.qq.com/miniprogram/introduction/)）。个人主体走的是**实名认证 / 个人认证**，两者日常容易被混着叫。判断方法：

- 后台**没有生成 300 元认证订单** → 你做的是个人实名认证，正常，不用管它叫什么；
- 后台**真的出现了 300 元微信认证订单** → 说明这个账号主体可能不是个人，回来告诉我，我们重新对一遍。

个人主体对后续流程的硬约束（照做即可，不需要改已提交的备案）：

| 项目 | 个人主体下的要求 |
|---|---|
| 域名实名认证 | 必须用**你本人姓名 + 身份证**，不能填公司/工作室名称 |
| 域名 ICP 备案主体 | 同上，也是你本人，与小程序主体一致 |
| 小程序备案材料 | 身份证正反面 + 本人实名手机号 + 精确到门牌号的通讯地址（与你已提交的一致，无需重做） |
| 服务类目 | 只能选个人可申请的（工具/效率一类），**报不了医疗健康**——这正是 [0.2](#02-疫苗模块推荐库降级为疫苗名字典已确定并已实施) 要降级疫苗模块的原因 |
| 小程序名称 | 不得含企业/商城类词汇，也不能与已有企业主体小程序重名 |
| `<web-view>` 业务域名 | 个人主体**不支持**配置——本项目不使用 `<web-view>`，无影响 |

另外：个人主体不能开通微信支付、部分高级接口受限——本项目都不涉及。

### 0.2 疫苗模块：推荐库降级为「疫苗名字典」（已确定并已实施）

风险集中在「**平台主动给医学建议**」，而不是「**用户自己记接种记录**」。所以拆成两块分别处理：

| 部分 | 风险 | 处理 |
|---|---|---|
| 接种记录（用户自主录入） | 低——等同记账本 | **完整保留** |
| 推荐疫苗库（按宝宝月龄推荐接种时间） | 高——接近疫苗/药品信息服务 | **降级**：只留名称/剂次/一类二类标签 |

即：**把平台从「给建议的角色」退回「给记事的角色」**。数据库表 `vaccine_library` 与种子数据**未改动**，用户的记录能力零损失。

落地口径（已实施，详见 [7.7](#77-疫苗模块降级已完成)）：
- 入口文案：`从推荐库添加` → `从疫苗名字典选择`
- 弹层标题：`推荐疫苗库` → `疫苗名字典`，副标题改为「仅提供疫苗名称与剂次，接种时间请按当地接种门诊安排」
- 去掉「建议月龄 2月~4月」展示、「适龄」高亮标签、按宝宝月龄预填计划日期；计划日期与接种日期**全部由用户自己填**
- 保留：一类/二类 tab、名称、剂次、类别标签、免责声明

已放弃的选项：B（换企业主体 + 《互联网药品信息服务资格证》等资质，成本高）、C（按工具类目赌审核通过，风险不可控）。

### 3.3 等待审核（三个环节）

| 环节 | 处理方 | 官方周期 | 注意事项 |
